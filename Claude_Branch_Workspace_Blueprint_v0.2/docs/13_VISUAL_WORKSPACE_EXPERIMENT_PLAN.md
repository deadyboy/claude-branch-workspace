## 3 数据语义与界面约定

### 3.1 复用已有对象

| 对象 | 现有依据 | 界面语义 |
|---|---|---|
| Project | id、rootPath | 某个执行端能够访问的目录 |
| Branch | parentBranchId、forkFromNodeId、workspaceMode | 可持续交互的对话分支 |
| ConversationNode | parentNodeId、branchId、消息引用、status | 一轮对话；只有已完成轮次作为本轮分叉候选 |
| RuntimeSession | adapterType、externalSessionId | 承载持久会话的运行时绑定 |
| AgentRun | ownerBranchId、ownerNodeId、parentAgentRunId | 一次可观察执行及其父子关系 |
| Task | 按 E5 所需最小新增 | 任务说明、所属项目、执行分支、尝试记录和结果引用 |
| Artifact | 按 E4、E8 所需最小新增 | 可定位的成果及来源；包括文件、报告或改动集合 |

先核对 packages/domain/src/types.ts 和现有服务，再决定是否需要 schema 迁移。Conversation 和 Workspace 暂不为了画图额外建表。新增 Task/Artifact 时保持既有 ID 和会话映射，迁移须验证旧数据可读。

### 3.2 三个视图

- Conversation：以真实轮次和父子分支构成树或森林；选中节点在侧栏读上下文，在聊天区继续工作。主干按时间排列，分支沿分叉点展开；默认摘要，按需展开详情。
- Team：持久任务分支与临时 AgentRun 使用不同形状或分组。点选运行可跳到所属对话；临时运行只提供适配器实际支持的控制。
- Project：初版展示目录包含关系、任务执行关系、成果来源关系。代码 import/call 依赖和自动语义图不作为初版承诺。

继承消息按原始 nodeId 引用，不为每个分支复制拓扑节点。拖动只改变视图布局，不能改变历史父子关系。历史节点上的“继续”明确表示从此新建分支；分支末尾“继续”追加到该分支。引用另一分支结果显示引用关系，不能伪装成对话历史合并。

对话上下文回到历史轮次，不意味着文件回到历史版本。worktree 从创建时 Git HEAD 派生；界面在创建前明确显示这一点。失败、取消、运行中的轮次可以查看，但不可作为当前完成态分叉入口。

## 5 实验设计与通过条件

### E1 项目入口和执行位置

假设：用户能够判断任务会在哪台机器、哪个目录执行，并能切换项目。

步骤：通过 UI 添加 P1/P2；打开 P1，再切到 P2；刷新后恢复当前项目。测试 P3 各边界，检查运行时连接状态。连接远端时，输入一个仅本机存在的路径，必须得到明确的执行端路径错误。创建失败不能产生半成品项目或分支。

通过条件：上述场景全部正确；项目间聊天、状态和事件不混入；普通目录可正常共享模式聊天；不符合条件时 worktree 禁用并说明实际原因。显示 dirty 不等于整个项目禁止使用。项目名允许重复，以 ID 区分。

### E2 对话图及历史上下文

假设：图的关系与持久化历史一致，分叉不会带入分叉点后的对话。

步骤：加载 D1，对照节点关系清单；在 Main 第 2 轮建 A，在 A 再建 A1；从子分支的继承历史再分叉；同时保留 Main 第 3—6 轮。图上分别打开各分支，核对有效消息、分叉来源和选中对象。归档后验证仍可定位和阅读历史；重命名后关系不变。

真实验证：先在早期轮次写入随机标记 A，再在后续轮次写入随机标记 B；从 A 所在已完成轮次分叉，要求只返回已知标记。新子会话可返回 A，不能返回 B。检查数据库有效上下文和适配器输入，两者均不得含 B；B 不写入共享文件或项目记忆。共做 3 个独立样本，各包含一次子分支再分叉。

通过条件：拓扑和有效上下文逐项一致；同名分支不混淆；分叉后源历史内容不变；3 个真实样本均通过。结构性上下文泄漏任意一次即失败，不能靠重试覆盖。模型漏答 A 单独记为模型行为失败，不直接误判为数据泄漏。

### E3 从图上执行和恢复

假设：用户能在图上启动、观察、停止和继续持久分支任务。

步骤：在 P1 历史节点创建 worktree 分支，在 UI 发送“为已有函数增加空输入处理并运行现有测试”；观察启动、运行、完成或失败；检查真实文件改动和测试结果。另用模拟运行时控制延迟、错误、取消及事件乱序。执行期间切换分支、刷新页面、断开并恢复连接；只重启独立实验控制面验证恢复。

通过条件：状态终态与服务端一致；重复点击 Send/Fork 不创建重复操作；切换项目后过期请求不能写入新项目 UI；停止只作用于目标分支；失败有原因，重试形成新尝试并保留旧记录；终态不能永久挂在 running。原目录和其他 worktree 的文件内容保持原样。

恢复分两类：浏览器刷新与网络重连应重获已有执行；控制面崩溃后的进程和 pending 状态按已实现恢复策略终结或重新绑定，不承诺进程无缝存活，也不自动重复提交任务。给用户一个明确、可操作的恢复结果。

### E4 成果与改动审阅

假设：用户能知道本次工作改变了什么，并定位到来源。

E4a 只读成果审阅：P1 工作开始前记录 worktree HEAD 和干净状态；完成后展示相对基准的新增、修改、删除、重命名和未跟踪文件。覆盖“只产生未提交改动”与“运行中产生提交”两种情况，避免只看 git diff 漏掉结果。文本提供内容差异；二进制提供名称、大小与类型提示。P2 展示执行中声明并验证存在的报告文件。

通过条件：已知改动清单逐项一致，无遗漏或串入其他工作；文件链接指向所属 workspace。M1 成果关联 projectId、branchId、nodeId，存在可靠运行归属时再关联 agentRunId；可返回来源分支和轮次。M2 引入 Task 后再关联 taskId。共享目录存在并发写入时只能声称“工作区变化”，除非有独立证据，不标成某个 Agent 独占成果。

E4b 应用成果是 M2 必需能力：将改动接受回目标目录前，记录源基准、目标状态和操作 ID，先预览，再显式点击应用；冲突或目标已变更时停止并说明，禁止静默覆盖。合成项目必须测试成功、冲突、预览后目标变化、重复点击和应用中途失败。中途失败时目标须保持原状，或准确显示已应用部分、尚未应用部分及可用恢复入口；不能报成全部成功。不能把已读 Diff 当作已接受结果。M1 仅要求 E4a。

### E5 人工派工与并行团队

假设：用户能通过 UI 把同一目标拆成多个可接管的任务，而临时执行不会变成假持久分支。

步骤：使用自由任务表单创建两个持久任务分支，在独立 worktree 分别实现 P1 的函数改动与文档说明。运行中打开其中一个分支、停止该任务并继续另一任务；停止后发送补充指令。所有任务角色和名称可编辑。加入一项失败任务，验证重试尝试与历史结果的对应关系。并发上限 3，超额显示排队。

通过条件：任务、分支、AgentRun、成果关系正确；两个任务确实发生执行时间重叠；干预目标明确；其他分支不受停止影响；重试不丢旧记录。临时 subagent 展示真实可观察事件；若不支持独立聊天或停止，禁用对应按钮并给出所属持久分支入口。

### E6 主 Agent 动态委派

假设：已有 MCP 控制能力能在 UI 中形成可理解、可追踪的团队流程。

步骤：在主分支交付一个合成项目任务，要求主 Agent 自行决定分工，通过实际注册的项目 MCP 工具创建持久工作分支、发送任务、获取结果，并生成汇总。MCP 在 UI 创建的主会话中的注册与可调用性先做一次能力验证；不能用开发者手工启动的外部主控替代产品内入口。再触发一个原生临时 subagent，验证两类对象分别呈现。

执行 3 个独立任务场景：两个独立成果、一个 worker 失败、用户中途干预。每场景并发上限 3。角色和委派数由任务决定，不把测试样例固化成产品流程。

通过条件：主会话、工作分支、任务、临时运行均有真实 ID 关联；用户可沿图找到任务指令与返回结果；汇总中的成果引用可打开；失败被主控感知并展示。若产品内主会话无法接入 MCP，则 E6 判 BLOCKED，并明确记录 M2 尚未完成。

### E7 性能和连续使用

固定同一 Windows 机器、Chrome 版本、生产构建、视口和显示缩放，记录设备配置。使用 D2/D3，每个数据集预热 1 次后测 5 次装载；交互至少 30 次；持续推送 20 条模拟事件/秒共 10 分钟。报告原始样本、每次结果及汇总，不用 5 次装载估算稳定的尾部概率。

预设目标：D2 每次从图数据到达至可操作不超过 1 秒；D3 不超过 3 秒；节点选择到详情可见 p95 不超过 200 毫秒（数据已加载）；事件接收到状态呈现 p95 不超过 1 秒。终态在乱序和重复事件后仍与服务端一致。超标先定位布局、数据量、订阅重绘或渲染，允许折叠和按需加载，但不能删除关系来通过。

M1 至少通过 D2、30 次交互和刷新恢复；M2 增加 D3、事件负载和 10 分钟持续使用。浏览器性能与模型等待分别计时；不把模型生成耗时算作图形渲染延迟。

### E8 项目关系图

假设：项目图帮助用户从成果追溯工作，也适用于非代码项目。

步骤：分别在 P1/P2 建立包含关系和任务成果链接；点击成果到文件，再到产生它的任务、对话与执行。对照固定关系清单；文件重命名、删除、未生成时分别显示当前状态。较大目录按层展开，排除 .git、依赖缓存及凭据文件等默认无关内容。

通过条件：规定范围的关系清单 100% 可定位；不存在的文件不能显示为可打开；推测或人工添加的关联明确标注来源。选中任一成果后，用户可在 3 次导航操作内到达来源对话。目录树、任务关联和语义依赖各自标明类型，不能宣称已经理解任意代码结构。

### E9 用户操作对照实验

目的：确认新 UI 是否改善非线性工作的理解与操作。主要评价者为项目用户本人；如可获得另 2—4 名目标使用者，再做探索性复验。单人结果只支持本项目的产品决策，不作总体用户统计推断。

对照 A 为 a20f7b6 旧界面；B 为新界面。旧界面缺失的任务记“功能不支持”，不虚构耗时用于计算提升。可共同完成的任务使用等规模不同内容的 D2 样本；单人先练习再做 A/B、B/A 两轮；多人分配不同顺序，减少熟悉效应。

| 任务 | 成功判据 | 预设时限 |
|---|---|---|
| U1 找到指定分叉点和两个后代 | 选中正确对象并说明关系 | 60 秒 |
| U2 从指定历史轮次创建分支并继续 | 分叉点正确，消息进入新分支 | 90 秒，不含模型等待 |
| U3 找到运行任务并停止目标 | 目标正确，其他任务继续 | 45 秒，不含运行时终止等待 |
| U4 找到失败原因并发起重试 | 旧失败保留，新尝试关联正确 | 90 秒，不含模型等待 |
| U5 找到成果及来源 | 正确打开成果和来源对话 | 60 秒 |
| U6 打开第二个项目并确认执行位置 | 正确项目、目录和执行主机 | 60 秒 |

记录成功、耗时、误操作、求助次数、模型等待和 1—7 分操作难易评分。新界面六项均须最终独立完成，限时首次成功至少 5/6；严重误操作为 0；易用性评分中位数至少 5/7。对共同支持任务，描述 A/B 时间和错误差异；时间降低 25% 是改进目标，不是统计显著性声明。未达到目标时先调整交互，再由用户完成新样本复验。

## 6 真实运行样本量与停止规则

模拟实验覆盖所有边界，结果必须全部通过。真实实验先完成 1 次单分支冒烟，再做 E2 的 3 次历史分叉场景和 E3/E4 的 3 次完整工作链路；M2 做 E5 两个场景和 E6 三个场景。每个场景可能包含多个模型调用，记录实际请求次数、运行时间及运行时可提供的用量，不把场景数当调用数。

相同原因连续失败 2 次则暂停该类真实实验并定位；模拟缺陷未修复前不反复消耗真实模型。原始失败保留，修复后的重跑绑定新版本号。运行时现有默认超时在首轮记录并固定，若调整须说明原因并重跑受影响比较。真实实验开始前明确使用现有额度还是付费入口及预算上限；未确认付费边界时只执行模拟部分。

数据串线、上下文泄漏、覆盖非目标文件、伪造执行成功或错误应用改动，任一发生即阻断该里程碑。模型回答不符合任务、网关失败和 UI 故障分别归因。不能只展示成功样本。

## 9 记录格式与验收决策

每个场景最少记录：实验编号、时间、代码提交、环境、运行时与模型、fixture 版本、操作步骤、预期、实际、耗时、PASS/FAIL/BLOCKED、证据位置、原因和复验编号。只保存定位问题所需的日志、截图和结果，不收集无关会话。

同一次运行的目录建议包含 manifest.json、results.json、必要 screenshots 和 traces；只有实验执行时才创建这些产物。截图证明界面表现，数据库与文件校验证明正确性，真实运行记录证明链路；三者不能相互替代。

| 结论 | 条件 |
|---|---|
| PASS | 对应里程碑必需实验全部通过，真实运行与 UI 证据齐全 |
| PARTIAL | 已有可用路径，但明确列出的验收项尚未完成 |
| FAIL | 出现可复现的实现缺陷或违反核心不变量 |
| BLOCKED | 必需环境、授权或运行时能力欠缺，无法完成对应实验 |

产品最终验收句：用户打开受支持执行端上的项目后，无需命令行操作业务流程，即可理解对话图、从历史创建工作分支、委派和接管工作、查看结果与来源，并在重新打开后继续。初始安装、认证和部署属于环境准备，单独记录。
